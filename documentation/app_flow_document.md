# codeguide-web-translator App Flow Document

## Onboarding and Sign-In/Sign-Up
When a new user arrives at the application, they are greeted by the public landing page served at the root URL. This page presents the core translator interface immediately so that visitors can test the translation feature without creating an account. Above the translator UI, a banner provides links to sign up or sign in if the user wants to save translation history or access personalized features. When a user clicks the "Sign Up" link, they are taken to a dedicated registration page. On this page, they enter their email address, choose a secure password, and confirm that password before submitting the form. Upon submitting, the user receives a confirmation email and is redirected to the sign-in page. To sign in, the user enters their registered email and password on the login page and submits the form. Successful authentication redirects them into the protected area of the app. If the user forgets their password, they can click the "Forgot Password" link on the sign-in page, provide their email address on a reset page, and then follow a secure link sent by email to create a new password. After resetting, they are returned to the sign-in page. The user can also sign out at any time by opening the user menu in the header and selecting "Sign Out," which clears their session and returns them to the public landing page.

## Main Dashboard or Home Page
Once authentication succeeds, the user lands on the main dashboard located at `/app/dashboard`. The dashboard features a persistent sidebar on the left and a top header bar. The sidebar lists the main sections: Translator, My Translations, and Settings. The header bar shows the application logo on the left and the user’s avatar and name on the right. The central content area of the dashboard begins with a welcome message and a snapshot widget that shows recent translation activity or usage statistics for the current session. The sidebar allows the user to navigate seamlessly between the translator interface, their saved translations list, and their account settings. Clicking on any menu item updates the central panel without requiring a full page reload, preserving the context and user data across navigation.

## Detailed Feature Flows and Page Transitions
When the user selects the Translator item in the sidebar, the central panel transitions to the translator page at `/app/translator`. This page displays a large text area for typing or pasting text and a file upload control for importing `.txt` files. Above the input area are two language selectors implemented with a dropdown component: one for the source language and one for the target language. Below these inputs is a button labeled "Translate." When the user clicks this button, the UI disables further input and displays an inline progress indicator. A fetch request is sent to the server-side endpoint at `/app/api/translate/route.ts`, carrying the text or file contents and the chosen languages. The server route applies rate limiting and then calls the OpenAI GPT-4.1-mini model with the secure API key. As the response arrives, the progress indicator updates and then disappears once processing finishes. The translated text appears in a read-only text area below, and a new button labeled "Download Result" becomes active. When clicked, this button triggers client-side logic to create a `.txt` file from the translated content and download it to the user’s device.

If the user clicks My Translations in the sidebar, the dashboard panel switches to the saved translations page at `/app/history`. This page lists each past translation entry with its date, source and target languages, and a snippet of the original text. Selecting an entry expands it in place, showing the full original text and the translated result, and offers a download link or a delete icon. All interactions occur within the same page context without a full reload.

## Settings and Account Management
By clicking Settings in the sidebar, the user enters the account management page at `/app/settings`. This form-based page displays the user’s profile information, including name and email, both editable. Below the personal details, there is a section for updating the password, which requires entering the current password followed by the new password and confirmation. Further down, theme preferences allow toggling between light and dark mode, and notification preferences let the user opt in or out of email alerts for new features or usage updates. After making changes, the user clicks the "Save Changes" button, and the application validates the inputs, updates the user record in the database, and displays a confirmation message. A link in the header then allows returning to the Translator or My Translations pages.

## Error States and Alternate Paths
If the user provides an invalid email or a password that fails complexity rules during sign-up or password reset, the form displays an inline error message under the relevant field and prevents submission. On the sign-in page, entering wrong credentials shows a general error banner at the top advising the user to check their email and password. During translation requests, if the file upload fails or the text exceeds allowed length, the translator page displays an error box above the inputs explaining the issue and suggesting corrective actions. If the OpenAI API call fails due to rate limiting, network errors, or content moderation flags, the API route returns a structured error response that the client displays in a prominent alert. In the event of connectivity loss, the UI shows an offline banner and disables features until the connection is restored. All error messages include a clear prompt to retry or return to a safe state, and the user can resume normal flow once the underlying issue is resolved.

## Conclusion and Overall App Journey
The user journey begins at the public landing page where translations can be tested immediately or the user can choose to sign up for a richer experience. After authenticating, the user is dropped into the dashboard, which serves as the central hub for translating text, viewing translation history, and managing account settings. From the translator page, they can type or upload content, choose languages, and trigger an API-backed translation, then download the result. The My Translations page provides a persistent record of past work, and the Settings page keeps personal information and preferences up to date. Throughout the flow, the user encounters clear navigation, inline feedback for errors, and consistent UI patterns driven by `shadcn/ui`. This end-to-end experience ensures that from sign-up to everyday use, the application remains intuitive, robust, and focused on delivering translation functionality securely and efficiently.
